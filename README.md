# РБД 2.0 — оновлена надбудова на базі погодженого інтерфейсу

Основа: надані користувачем `taskpane(5).html`, `taskpane-v3(8).js`, `RBD_ACTIVITY_SETUP(1).txt`.
Не є новим спрощеним інтерфейсом: оригінальні форми, KPI, таблицю, кольорові рядки, панель історії та нагадування збережено.

## Файли
- `taskpane.html` — початковий повний інтерфейс + адаптивність та зелена тема.
- `taskpane-v3.js` — оригінальна логіка, збережена для сумісності з макетом.
- `adapter.js` — адаптація до нової структури Excel та команд; підключається після старого JS.
- `manifest.xml` — шаблон надбудови. Перед встановленням налаштувати HTTPS-домен.
- `icon-*.png` — піктограми.

## Структура даних
Читає новий реєстр `RBD_Requests` або таблицю з українськими заголовками «ID заявки», «Статус», «Виконавець». Старий `tbl_RBD_Base` — резервний варіант.
Підтримує колонки «Тема заявки», «Опис заявки», «Місто», «Локація», «Статус», «Категорія», «Замовник», «Виконавець», «ID ERP». Неіснуючі значення сум, SLA, дат не вигадує.
Довідники: `RBD_Users`, `RBD_Statuses`, `RBD_Cities`, `RBD_Locations`, `RBD_Categories`, `RBD_Customers`, `RBD_Priorities` за наявності. Для міст, локацій, категорій, замовників потрібне реальне наповнення таблиць.
Кабінети: «Іванченко», «Войцехівський», «Ридванський», «Галько», «Трунов», «Желясков», «Слепущенко», «Сергеєв», «Туровський», а також «Кабінет керівника»; підтримуються старі назви вкладок.

## Запис команд
Надбудова знаходить на вкладці активного кабінету таблицю Excel з заголовками «ID команди» і «Дія» та дописує команду у її кінець. Підтримано: «Створити», «Змінити статус», «Закрити», «Призначити», «Коментар» (за умови підтримки основним процесором РБД). Команда отримує стан «Нова» і у цей момент ЩЕ НЕ виконана. Для застосування змін запустіть чинний сценарій обробки команд вручну.
ВАЖЛИВО: старий `UPDATE` (одночасне редагування багатьох полів) не входить до переліку дій нової черги; у такому випадку інтерфейс повідомляє про відсутність підтримки і НЕ прикидається, що дані збережені. Призначення через стару форму редагування також потребує окремого явного керування процесором, автоматично не активовано.

## Історія та нагадування
Читання подій: `RBD_Events` (або українська таблиця історії), `RBD_Reminders`, резервно `tbl_RBD_Activity`. Примітки записуються в `RBD_Events`, нагадування — `RBD_Reminders`. Стару `tbl_RBD_Activity` не видаляє.
Лог історії статусів має надходити від процесора після фактичної зміни в базі: адаптер не вигадує завершених переходів.

## Публікація
1. Завантажте усі файли, крім README, на один HTTPS-сервер.
2. У manifest.xml змініть `https://YOUR-HTTPS-DOMAIN.example` на свій реальний HTTPS-домен.
3. Додайте manifest.xml як власну надбудову через засоби Microsoft 365, якщо це дозволяє політика компанії.
4. Відкрийте книгу РБД 2.0 на вкладці кабінету та запустіть надбудову.

## Межі поточної версії
Код пройшов локальну перевірку синтаксису JS; інтеграційні тести у вашому корпоративному Excel не виконані. Права реальних користувачів не забезпечуються лише назвою активної вкладки; потрібна Microsoft 365 авторизація / серверна перевірка прав. ERP-синхронізація й автоматичне виконання команд не налаштовані. Після перевірки реальних назв таблиць може знадобитися корекція адаптера.
