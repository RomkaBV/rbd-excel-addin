# РБД — контрольна точка та промпт для продовження

Дата: 23.10.2026. Це проміжний стан розробки, не підтвердження роботи у справжньому Excel.

- Затверджений макет користувача: «Панель заявок РБД з листуванням(3).png».

## Уже зроблено в коді

1. `taskpane.html`: замінено нижню частину форми на дві постійні колонки. Прибрано старі стилі drawer, усі шари CSS 3.3.5–3.4.8 для цієї форми й кнопки згортання. Єдиний стиль компонента — `rbd-workspace.css`.
2. Історія — семантична таблиця, чотири вкладки (усі / статуси / примітки / листування), поле примітки й кнопка «Додати» постійно внизу. Правий переглядач не змінюється від фільтра зліва.
3. Лист і нагадування — окремі діалоги `rbdMessageDialog` / `rbdReminderDialog`. Існуючі ID полів і Excel-функції запису збережені. Експорт нагадувань через `rbd-reminder-export.js` лишився.
4. `rbd-google-ui.js` — переписаний контролер листування: локальні файли прив'язані до ID заявки; немає змішування файлів між заявками; захист від запізнілих API-відповідей; drag/drop; картки; відкриття / завантаження; повтор завантаження. Чернетки Excel лишаються в історії й не видаються за оригінали листів.
5. `rbd-mail-viewer.js`, `rbd-mail-worker.js`, `src/mail-parsers.js`: постійний inline reader, MIME через postal-mime, MSG через @kenjiuno/msgreader; парсинг у Worker із таймаутом. Вкладення можна завантажити. HTML очищується DOMPurify і показується у sandbox iframe з CSP, зовнішні ресурси заблоковані. Outlook для оригіналу — чесний fallback завантаження.
6. `rbd-sla.js`: окремий чистий розрахунок календаря та перебувань; повторний вхід має окремий SLA; поточне прострочення лише поточного перебування, загальне — сума додатних перевищень; завершений статус не втрачає зелений колір після повернення назад; час після завершення не старить повторно відкриту заявку; невідомі дати не перетворюються на вигаданий нуль.
7. `rbd-config.js`: публічна конфігурація, без секретів. Календар за замовчуванням збережено з реального коду РБД: Пн–Пт 09–18, 9 годин; обід не був налаштований. Інтервали дозволяють окремо задати обід/свята. Не підміняти цей графік непідтвердженим припущенням.
8. `src/entra-auth.js` / `rbd-auth.html` / `rbd-secure-google-bridge.js`: клієнт корпоративного входу Microsoft, Office Dialog + PKCE/MSAL, API-клієнт із 401/403, таймаутами. Конфігурація порожня, реальний вхід ще НЕ перевірено.
9. Локальні browser bundles в `vendor/`; зафіксовані npm-залежності, lockfile, команди build/check/test/test:ui. Версія та manifest/cache-busting — 3.4.9.

## Фактично перевірено на цій контрольній точці

- `npm run build` — успішно; парсери й MSAL зібрані локально.
- `npm test` — 6/6 тестів SLA пройшли.
- `npm run test:ui` — 6/6 Chromium/Playwright тестів пройшли: дві колонки; незалежність фільтрів/діалогів; MIME UTF-8/quoted-printable і вкладення; справжній бінарний MSG fixture з вкладенням; пошкоджений MSG; локальні файли різних заявок; 403 та запізніла відповідь; вузьке вікно.
- Office.js у тестах підмінений; реальні Excel-записи та корпоративний Entra-вхід не перевірено.
- Знімки браузера лежать локально у `test-results/`, не є новим дизайном.

## Що ще необхідно доробити

1. Переглянути screenshot desktop/narrow та усунути проблеми відображення. Додати важливі тести збереження примітки/нагадування через Excel mock, без реального запису користувацьких даних; HTML-листа з небезпечним вмістом; успішного API list/get/upload і 401/timeout.
2. Запустити `npm run check` та перевірити решту посилань/DOM. Перевірити збір ліцензій усіх транзитивних browser dependencies.
3. `server/server.mjs` на цій точці ще СТАРИЙ каркас із 503. Потрібно реалізувати Entra JWT signature/issuer/audience/tid/scope/exp, серверний ACL для заявки, Google Drive list/get/upload з перевіркою належності файла дозволеній папці, ідемпотентністю, лімітами; перевірити на тестових драйверах/токенах.
4. Фактичний запуск приватного Drive заблокований не кодом UI, а відсутністю розгорнутого HTTPS backend, Entra tenant/client/scope і приватних серверних Google credentials та ACL. Не відкривати папку публічно, не використовувати Anyone/execute-as-owner Apps Script.
5. `RBD_Sandbox_340.gs` і тестовий Apps Script користувача — лише синтетичний тест, не готовий доступ до приватного архіву. Не під'єднувати їх до робочих заявок.
6. Після завершеного перевіреного етапу опублікувати атомарний коміт через GitHub tool (без force), звірити актуальну main на паралельні зміни. Поточна гілка — збереження незавершеної роботи; main поки не оновлена.
7. Оновлювати цей HANDOFF при кожному наступному збереженні; явно розрізняти написаний код, локальні тести, роботу в Excel і фактичне розгортання сервера.

## Готовий промпт для нового чату

Продовж розробку Excel-надбудови РБД у https://github.com/RomkaBV/rbd-excel-addin. Спочатку прочитай актуальний `docs/HANDOFF.md` з гілки `codex/rbd-workspace-3.4.9`, перевір останні коміти цієї гілки та main. Не починай з нуля. Затверджений макет — «Панель заявок РБД з листуванням(3).png»: постійні рівні колонки історії й листування, примітка внизу зліва, список оригіналів та inline-переглядач справа, редактори окремо, ніякого згортання. UI рефакторинг, MIME/MSG reader та по-візитний SLA вже написані й мають локальні тести. Прочитай блок незавершеного у HANDOFF, продовж код і перевірки, потім атомарно збережи через GitHub. Захищений Drive потребує реального Entra/backend/ACL; не підміняй його анонімним Apps Script і не заявляй про роботу в Excel на підставі лише синтаксису чи коміту. Періодично зберігай контрольні точки й оновлюй HANDOFF. Не проси користувача перевіряти кожну дрібницю.
