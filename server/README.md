# RBD API — розгортання (поки без доступу до Google)

## Важливо
Це захищений каркас, **не готовий сервер завантаження**. Усі /api/requests/... повертають 503 до впровадження перевірки прав на заявки та Google-сховища.

## Необхідні дії адміністратора
1. Зареєструвати Microsoft Entra застосунок для RBD API (однотенантний), налаштувати API audience/scope та дозволи користувачів.
2. Забезпечити Office add-in дійсним access token для RBD API. Токен має мати належні claims/scopes; сервер повинен перевіряти scope/roles додатково до підпису JWT до production.
3. Визначити джерело ACL заявок (серверно підконтрольний реєстр із незмінними ID працівників). Не вважати назву Excel вкладки або client-side STATE.actor підтвердженням прав.
4. Створити приватний HTTPS host із секретами в налаштуваннях середовища, а не у репозиторії.
5. Налаштувати легальний контрольований сервісний доступ до Google Drive і Google Sheets. Облікові дані власника не пересилати в чат і не розміщувати у GitHub.
6. Провести перевірку політики STV Group щодо зберігання ділового листування в Google.

## Локальна перевірка
Встановити Node.js 20+, перейти до папки server, виконати npm install. Виставити ENTRA_TENANT_ID, ENTRA_API_AUDIENCE, RBD_ORIGIN, PORT у приватному середовищі. Запустити npm start. GET /health поверне {status:"ok",googleConnected:false}. Це **не** означає, що завантаження працює.

## Перевірки перед ввімкненням
- Без токена /api/... -> 401
- З коректним токеном і без ACL -> 503
- Після реалізації ACL чужий requestId -> 403
- Кожне нагадування ідемпотентне за ID
- Під час тесту усі надсилання лише на roman.barzo@stv.group, іншим адресатам не відправляти
- Приватний файл Google Drive не відкривається через публічний URL
